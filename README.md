
Асинхронный веб-сервис для бронирования и покупки билетов на мероприятия, спроектированный с учетом высокой конкурентности при нагрузках.
Проект построен на современном асинхронном стеке и решает типичные проблемы высоконагруженных систем:

1. Контроль гонки данных (Race Conditions)
Эндпоинт покупки билетов (/api/tickets/buy) использует пессимистичную блокировку строк (with_for_update()) на уровне базы данных. Это исключает возможность двойной продажи одного и того же билета при одновременных запросах.

2. Обеспечение идемпотентности
Реализована защита от повторной отправки запросов (например, при сбоях сети у клиента) с помощью заголовка X-Request-ID и кэширования ответов в Redis.

3. Rate Limiting (Защита от DDoS и спама)
Пользовательская активность ограничена на уровне Middleware: не более 5 запросов в секунду с одного IP-адреса. При превышении лимита возвращается код ответа 429 Too Many Requests.

4. Асинхронная фоновая обработка
Тяжелые операции (генерация PDF-билета и отправка уведомления на электронную почту) делегированы в фоновые задачи Celery с брокером сообщений Redis, что минимизирует время отклика API.

5. Кэширование
Часто запрашиваемые данные (список популярных событий) кэшируются в Redis с механизмом инвалидации при изменении данных.


Фреймворк: FastAPI
База данных: PostgreSQL , SQLAlchemy 2.0 (AsyncIO) + Alembic (миграции)
Кэш и брокер сообщений: Redis
Очередь задач: Celery
Валидация: Pydantic v2
Контейнеризация: Docker, Docker Compose

Быстрый старт

1. Клонируйте репозиторий

2. Запустите сервисы в фоновом режиме: docker compose up --build -d

3. После запуска документация API будет доступна по адресу: http://localhost:8000/docs
